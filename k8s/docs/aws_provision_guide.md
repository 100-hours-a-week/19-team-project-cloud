# 초소형 K8s 클러스터 가성비 끝판왕 (All Public Subnet) 구성 가이드

NAT Gateway 비용(월 약 4.5만원)마저 완벽히 제거하기 위해, **모든 자원(마스터, 워커, ALB)을 퍼블릭 서브넷에 배치**하여 구축하는 AWS 콘솔 매뉴얼입니다.

---

## Step 1. VPC & 서브넷 (네트워크 뼈대)
AWS 콘솔에서 **[VPC]** 서비스 접속

1. **VPC 생성**
   - **이름 태그**: `refit-mini-vpc`
   - **IPv4 CIDR**: `10.2.0.0/16` (권장)
   
2. **퍼블릭 서브넷 2개 생성** (NAT가 없으므로 프라이빗 서브넷은 만들지 않습니다)
   - **서브넷 1 (`-a` 구역)**:
     - 이름: `refit-pub-a` / 가용 영역: `ap-northeast-2a` / CIDR: `10.2.1.0/24`
   - **서브넷 2 (`-c` 구역)**: (ALB 고가용성 제약조건 때문에 빈 방이라도 1개 더 필요)
     - 이름: `refit-pub-c` / 가용 영역: `ap-northeast-2c` / CIDR: `10.2.3.0/24`
   - ⚠️ **(중요)** 생성 직후 두 서브넷을 각각 선택 -> 작업 -> **[서브넷 설정 편집]** -> **"퍼블릭 IPv4 주소 자동 할당 활성화"** 반드시 체크 후 저장

3. **인터넷 게이트웨이(IGW) 생성 및 라우팅 연결**
   - **IGW 생성**: 좌측 메뉴 [인터넷 게이트웨이], 이름 `refit-igw` 생성 후 `refit-mini-vpc`에 **[VPC에 연결]**.
   - **라우팅 테이블**: VPC 메뉴 좌측 **[라우팅 테이블]**에서 `refit-pub-rt` 생성.
   - **라우팅 편집**: 누른 뒤 하단 [라우팅 편집], 대상 `0.0.0.0/0`, 타겟 방금 만든 `refit-igw` 추가.
   - **서브넷 연결 편집**: 하단 [명시적 서브넷 연결 편집], 앞서 만든 `refit-pub-a`, `refit-pub-c` 두 개 모두 체크 후 저장.

*(NAT 게이트웨이 생성 단계는 통째로 스킵합니다! 🎉)*

---

## Step 2. 보안 그룹 (퍼블릭 노출에 대비한 철통 방어막)
워커 노드가 외부 인터넷에 직접 맞닿게 되므로 보안(방화벽) 설정이 매우 중요합니다!

AWS 검색창에서 **[EC2]** 서비스 -> 좌측 메뉴 **[보안 그룹]** 클릭 (`refit-mini-vpc` 선택 필수)

1. **마스터 노드용 SG (`k8s-master-sg`)**
   - [인바운드 1] 유형: `SSH (22)` / 소스: **내 IP** (반드시 본인 PC IP만 허용!)
   - [인바운드 2] 유형: `사용자 지정 TCP` / 포트: `6443` / 소스: **10.2.0.0/16** (VPC 내부 워커 노드들만 API 접근 허용)
   - [인바운드 3] 유형: `모든 트래픽` / 소스: 방금 생성된 마스터 SG 자신(sg-xxx) (자기들끼리 통신)

2. **워커 노드용 SG (`k8s-worker-sg`)**
   - [인바운드 1] 유형: `SSH (22)` / 소스: **내 IP** (워커에도 직접 접속 가능해져서 편합니다)
   - [인바운드 2] 유형: `사용자 지정 TCP` / 포트: `30080` / 소스: **10.2.0.0/16** (VPC 내부망 대역) 및 나중에 만들 **ALB 보안 그룹** 추가
   - [인바운드 3] 유형: `모든 트래픽` / 소스: 워커 SG 자신(sg-xxx) (워커 내부 통신)
   - [인바운드 4] 유형: `모든 트래픽` / 소스: 마스터 SG(sg-xxx) (마스터가 워커 제어)
   - ⚠️ **절차상 주의**: 워커 노드가 퍼블릭에 있어도, 외부 사용자는 30080 포트를 напрямую 치고 들어오지 못하게 하고 "ALB"에서만 우회해서 들어오게 해야 안전합니다.

3. **ALB용 SG (`k8s-alb-sg`)**
   - [인바운드 1] 유형: `HTTP (80)` / 소스: `Anywhere-IPv4 (0.0.0.0/0)`
   - [인바운드 2] 유형: `HTTPS (443)` / 소스: `Anywhere-IPv4 (0.0.0.0/0)`

## Step 3. EC2 인스턴스 (서버) 생성
전부 퍼블릭 서브넷(A구역)에 띄워버립니다.

EC2 화면 좌측 메뉴 **[인스턴스] -> [인스턴스 시작]**

1. **Master Node (마스터)**
   - 이름: `refit-master`
   - 스펙: **Amazon Linux 2** / `t3.medium`
   - 키 페어: 기존 `refit` 키 사용
   - 네트워크 설정: VPC `refit-mini-vpc` / 서브넷 **`refit-pub-a`** / "퍼블릭 IP 자동 할당 활성화" / 기존 보안 그룹 선택 `k8s-master-sg`
   - 스토리지: **gp3 (50GB)** (크기 직접 입력하고 고급 눌러서 gp3 선택)

2. **Worker Node (워커)**
   - 이름: `refit-worker`
   - 스펙: **Amazon Linux 2** / `t3.large`
   - 키 페어: 기존 `refit` 키 사용
   - 네트워크 설정: VPC `refit-mini-vpc` / 서브넷 **`refit-pub-a`** / "퍼블릭 IP 자동 할당 활성화" / 기존 보안 그룹 선택 `k8s-worker-sg`
   - 스토리지: **gp3 (100GB)**

※ 이제 마스터와 워커 노드 모두 프라이빗이 아니므로 외부 IP(퍼블릭 주소)를 부여받게 되며, 도커 이미지를 다운받을 때 NAT 게이트웨이 대신 각자의 무료 퍼블릭 통신(IGW)을 타고 다운로드합니다.

---

## Step 4. 로드밸런서(ALB) 앞단 배치
외부 사용자가 웹소켓과 API를 타고 워커 노드로 안전하게 들어올 통로를 구축합니다.

1. **타겟 그룹(Target Group) 생성**
   - 메뉴 타겟 그룹 -> 타겟 그룹 생성
   - 타겟 유형: `인스턴스`
   - 대상 그룹 이름: `refit-tg`
   - 프로토콜/포트: `HTTP` / `30080` (나중에 K8s Gateway API NodePort로 쓰임)
   - 네트워크: `refit-mini-vpc` 선택
   - ➡️ 다음 버튼 누르고 뜬 화면에서 `refit-worker` 인스턴스를 체크하고 "아래에 보류 중인 것으로 포함" 클릭 뒤 타겟 그룹 생성.

2. **ALB 생성**
   - 로드밸런서 메뉴 -> Application Load Balancer 생성
   - 이름: `refit-alb` 
   - 체계: `인터넷 페이싱 (Internet-facing)` 
   - 네트워크 매핑: VPC 고르고, 서브넷 **`refit-pub-a`와 `refit-pub-c` (두 군데 다!)** 체크. (워커는 a에만 있지만 밸런서는 무조건 두 개 다 체크해야 생성됨)
   - 보안 그룹: `k8s-alb-sg`
   - 리스너: HTTP : `80` 라우팅 동작을 규칙 전달(Forward to) -> 방금 만든 `refit-tg` 연결 후 생성 완료.

3. **(핵심) 웹소켓 보호 세팅**
   - 생성된 ALB 이름 누르고 상세 정보 진입
   - **[속성 (Attributes)]** 탭 선택 -> 편집 누르기
   - **`유휴 제한 시간 (Idle timeout)` 값을 60에서 반드시 `3600`초 (1시간)으로 늘려두기.** (이걸 안 하면 채팅 중에 AWS가 칼같이 연결을 뺏어갑니다)
